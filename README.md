**Название проекта:** «Трекер заметок».
Это веб-приложение для создания, хранения и организации личных заметок. Пользователь сможет добавлять новые записи, просматривать список заметок, открывать отдельную заметку, редактировать и удалять ее. Для удобной навигации заметки можно будет искать по заголовку и фильтровать по категории или тегам.

Целевая аудитория проекта — пользователь, которому нужно быстро фиксировать учебные, рабочие и личные мысли в одном месте.


## 🖥️ Основные экраны

### 1. Главная страница (лендинг)
- Отображается для неавторизованных пользователей.
- Содержит кнопки **«Войти»** и **«Зарегистрироваться»**.
- После входа перенаправляет в список рабочих областей.

### 2. Регистрация и вход
- **Регистрация**: форма создания аккаунта (имя пользователя, email, пароль).
- **Вход**: форма аутентификации по email и паролю.
- После успешного входа пользователь попадает на страницу своих рабочих областей.

### 3. Профиль пользователя
- Просмотр и редактирование личных данных.
- Отдельная форма для смены пароля.
- Доступен только авторизованным пользователям.

### 4. Список рабочих областей 
- Отображает все рабочие области, к которым у пользователя есть доступ.
- Позволяет создать новую рабочую область.
- Переход к заметкам внутри выбранной области.

### 5. Список заметок в рабочей области 
- Показывает заметки только выбранной рабочей области.
- Реализованы **поиск по заголовку/тексту**, **фильтрация по категориям** и **сортировка** (по дате создания, по названию).
- Кнопка **«+ Новая заметка»** ведёт на форму создания.
- Каждая заметка кликабельна и открывает страницу просмотра.
- Для владельца области доступно управление участниками (добавление/удаление).

### 6. Создание заметки
- Форма с полями: заголовок, текст, категория, теги.
- Можно создать новую категорию прямо из формы.
- После сохранения происходит переход на страницу созданной заметки.
- Есть возможность отменить создание и вернуться к списку.

### 7. Просмотр заметки
- Отображает заголовок, полный текст, категорию, теги, дату создания и последнего изменения.
- Кнопка **«Редактировать»** ведёт на форму редактирования.
- Кнопка **«Удалить»** открывает подтверждение; после удаления происходит возврат к списку заметок рабочей области.

### 8. Редактирование заметки
- Форма предзаполнена текущими данными заметки.
- После сохранения — переход на обновлённую страницу просмотра.
- Можно отменить изменения и вернуться к просмотру без сохранения.

## 🔀 Переходы

```text
Главная (лендинг)
├── Войти → Форма входа → Список рабочих областей
├── Зарегистрироваться → Форма регистрации → Список рабочих областей
└── (для авторизованных) → Список рабочих областей

Список рабочих областей
├── Создать область → Новая область → Список заметок области
├── Выбрать область → Список заметок области
└── Профиль → Профиль пользователя

Список заметок области
├── + Новая заметка → Создание заметки → Просмотр заметки
├── Поиск / фильтры / сортировка → Обновлённый список
├── Выбрать заметку → Просмотр заметки
└── Управление участниками (для владельца) → Добавление / удаление участников

Просмотр заметки
├── Редактировать → Редактирование заметки → Просмотр заметки
├── Удалить → Подтверждение → Список заметок области
└── Назад → Список заметок области

Создание заметки
├── Сохранить → Просмотр созданной заметки
└── Отмена → Список заметок области

Редактирование заметки
├── Сохранить → Просмотр обновлённой заметки
└── Отмена → Просмотр заметки без изменений
```

##  Стек технологий

### Backend

- **Ruby** — основной язык программирования;
- **Ruby on Rails** — веб-фреймворк для маршрутизации, контроллеров, моделей и работы с базой данных;
- **SQLite** — база данных для учебной версии проекта;
- **Active Record** — работа с таблицей заметок и валидация данных.

### Frontend

- **HTML5** — структура страниц и форм;
- **CSS3** — оформление и адаптивная верстка;
- **ERB** — генерация HTML-шаблонов на стороне сервера;
- **JavaScript** — небольшие интерактивные элементы, например подтверждение удаления и фильтрация.


## Подводные камни

### Данные и датасеты

Внешний датасет не требуется: заметки создаются самим пользователем и хранятся в локальной базе данных. Нужно предусмотреть обязательные поля, ограничения длины и корректную обработку пустых или слишком больших значений.

### Открытые API

Для базовой версии открытые API не нужны. Это уменьшает количество внешних зависимостей и проблем с доступностью сервисов. В дальнейшем можно добавить API, например для получения цитат или автоматического определения категории.

### Сложная логика

- поиск по заголовку и тексту заметки;
- фильтрация по категориям и тегам;
- сортировка по дате создания или изменения;
- валидация формы создания и редактирования;
- подтверждение удаления, чтобы избежать случайной потери данных;
- корректное отображение пустого списка и результата поиска;
- обработка ситуации, когда запрошенная заметка не существует.

### Возможные ограничения

На начальном этапе приложение рассчитано на одного пользователя. Авторизация, совместный доступ, права пользователей и синхронизация между устройствами могут быть добавлены позже.
